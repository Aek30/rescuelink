# Phase 5 — ช่วงที่ 1: Text multi-hop

ทำเฉพาะการส่งแชต A → B → C และป้องกันวน/ซ้ำ ยังไม่เริ่มช่วงที่ 2 หรือ 3

## พฤติกรรม

- ถ้าผู้รับเชื่อมต่อโดยตรง ใช้ข้อความและ ACK แบบเดิม
- ถ้าไม่มีลิงก์ตรง ส่งซอง `relayVersion: 1` ไปยังเพื่อนบ้านที่รู้จักและเชื่อมต่อแล้ว โดยคง ID ผู้ส่ง ผู้รับ เนื้อหา และเวลาของข้อความเดิม
- เครื่องกลางส่งต่อไปยังเพื่อนบ้าน ยกเว้นเครื่องต้นทางของ hop และเครื่องที่อยู่ใน `relayPath` จำกัดสูงสุด 8 ลิงก์; hop สุดท้ายรับได้แต่ส่งต่อไม่ได้
- ตรวจว่า hop ล่าสุดตรงกับ identity ของ endpoint ที่แนะนำตัวแล้ว; ซอง relay รองรับเฉพาะข้อความแชต
- SQLite `relay_seen` บันทึก ID แบบ atomic ก่อนส่งต่อ กันแพ็กเก็ตซ้ำพร้อมกันและหลัง restart ฐานข้อมูลอัปเกรดจาก version 1 เป็น 2 โดยคงข้อมูลเดิม
- เครื่องกลางไม่บันทึกแชตของผู้อื่นในประวัติ ปลายทางบันทึกหนึ่งรายการต่อ ID และตรวจเนื้อหาขัดแย้ง
- ส่งซองจากต้นทางหนึ่งครั้งต่อ ID/เพื่อนบ้านใน session หลัง native send สำเร็จ; direct retry/ACK ยังใช้แบบเดิม
- จำกัดข้อความใหม่รวม envelope เดิมไม่เกิน 24 KiB เพื่อสำรองพื้นที่เส้นทางภายในเพดาน transport 32 KiB

## ขอบเขตและข้อจำกัดที่ตั้งใจไว้

- A ต้องรู้จัก ID ของ C จากการเคยเชื่อมต่อก่อน ยังไม่มี remote peer discovery
- B ต้องเชื่อมกับ A และ C พร้อมกัน; ใช้ Nearby `P2P_CLUSTER` เดิม
- ยังไม่มีคิวส่งต่อบน B หากลิงก์ขาด ส่งไม่สำเร็จ หรือ B ปิดระหว่างส่ง ข้อความอาจไม่ถึง C และการส่ง ID เดิมซ้ำไม่ทำให้ B ส่งใหม่
- ACK ผ่าน relay, retry ของเครื่องกลาง และ SOS/Rescue ผ่าน relay เป็นช่วงที่ 2
- ที่ A สถานะ SENT หมายถึงส่งให้เพื่อนบ้านแล้ว ไม่ใช่ C ยืนยันรับ; C เก็บเป็น DELIVERED ภายในเครื่อง แต่ไม่ส่ง ACK ข้าม relay
- ซอง relay ไม่ใช่ลายเซ็นดิจิทัล การตรวจ hop ไม่รับรอง identity ผู้ส่งต้นฉบับจากเครื่องกลางที่ไม่สุจริต
- ตาราง seen ยังไม่มีการล้างอัตโนมัติ เพื่อคงการกันซ้ำหลัง restart; ต้องกำหนด retention ร่วมกับอายุคิวในช่วงที่ 2
- ทุกเครื่องในเส้นทางควรใช้เวอร์ชันนี้ เครื่องเวอร์ชันเดิมไม่รองรับ relay

## การตรวจสอบ

`test/multi_hop_test.dart` จำลองสาม service และ SQLite แยกเครื่อง ตรวจ A → B → C, origin, ข้อความไทย/emoji, concurrent duplicates, restart, loop/path validation, hop limit, failed link และ migration จากฐานข้อมูลเดิม

ผล automated ไม่ใช่การยืนยันสัญญาณวิทยุจริง การทดสอบมือถือสามเครื่องและแก้บั๊กภาคสนามเป็นช่วงที่ 3 และยังไม่ได้ดำเนินการ
