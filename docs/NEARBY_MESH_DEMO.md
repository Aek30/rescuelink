# ทดสอบ RescueLink แบบส่งต่อผ่าน nodes

ติดตั้งแอป build เดียวกันทุกเครื่อง ตั้งชื่อ A, B, C (หรือชื่อไทย) เปิด Bluetooth / Wi-Fi และอนุญาตสิทธิ์ Nearby ที่แอปขอ ใช้บัญชีหรือโหมดผู้ใช้แยกกันในแต่ละเครื่อง

## เดโม 3 เครื่อง: A → B → C

1. เปิดแอป A และ B รอจนแสดงว่าเชื่อมต่อโดยตรง
2. วาง B ให้ติดต่อ A และ C ได้ แต่จัดระยะ A กับ C ให้พ้นระยะเชื่อมต่อโดยตรง แล้วเปิดแอป C
3. ตรวจว่า B เชื่อมทั้ง A และ C อยู่พร้อมกัน
4. ที่ A ตรวจว่าชื่อ C แสดงการส่งต่อผ่านเครื่องกลาง B แล้วส่งข้อความถึง C
5. ตรวจว่า C ได้ข้อความจาก A เพียงครั้งเดียว และสถานะข้อความที่ A เปลี่ยนเมื่อการตอบรับเดินทางกลับ C → B → A
6. ทดลองปิดแอป B หรือปิดวิทยุของ B เส้นทางจะขาด จากนั้นเปิด B ใหม่และรอระบบเชื่อมต่อ/ส่งข้อความที่ค้างอีกครั้ง

ถ้า A กับ C ยังเชื่อมต่อโดยตรง ระบบจะใช้ลิงก์ตรง การวางโทรศัพท์ 3 เครื่องติดกันจึงยังพิสูจน์การส่งต่อไม่ได้ หน้าจอต้องแสดงเครื่องกลางก่อนเริ่มส่งข้อความ

## เดโม 4 เครื่อง: A → B → C → D

จัดระยะให้มีเฉพาะคู่ข้างเคียงที่ติดต่อกันได้ แล้วส่งจาก A ถึง D ตรวจว่าข้อความผ่าน B และ C และมีการตอบรับย้อนกลับถึง A

## พฤติกรรมหลังปรับโค้ด

- โหลดชื่อโปรไฟล์ที่บันทึกในเครื่องและเตรียมตัวรับข้อความก่อนเริ่ม Nearby
- แยกชื่อที่แสดงออกจากชื่อบนสัญญาณ โดยใช้ UUID เลือกฝั่งเริ่มเชื่อมต่อ ชื่อไทยซ้ำกันจึงไม่ต้องใช้ชื่อเป็นตัวตัดสิน
- แต่ละเครื่องเริ่ม handshake ทีละเครื่อง แต่คงลิงก์ที่เชื่อมสำเร็จไว้หลายเครื่องได้
- handshake ค้างหมดเวลาใน 12 วินาที การล้าง native connection รอไม่เกิน 3 วินาที และฝั่งสำรองรอ 16 วินาทีก่อนลองเริ่มเอง
- รีเฟรชค้นหาทุก 12 วินาทีเมื่อว่าง แม้มีเครื่องเชื่อมแล้ว โดยงดรีเฟรชระหว่าง handshake และการรับ/ส่งไฟล์

เวลาจริงยังขึ้นอยู่กับโทรศัพท์ วิทยุ ระยะทาง และระบบ Android ต้องวัดบนเครื่องจริงก่อนนำเสนอ ตัวทดสอบอัตโนมัติจำลองการเชื่อมต่อและเส้นทางข้อความ ไม่ได้แทนการทดสอบสัญญาณจริง
