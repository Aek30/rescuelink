# การแก้ปัญหาจากการทดสอบโทรศัพท์สองเครื่อง

## พฤติกรรมหลังแก้ไข

- การเชื่อมต่ออัตโนมัติเลือกผู้เริ่มคำขอจากชื่อเครื่อง เพื่อลดคำขอสวนกัน ชื่อเหมือนกันยังใช้การหน่วงแบบสุ่ม ปุ่ม Connect แบบเลือกเองใช้ได้ทั้งสองฝั่ง
- เมื่อหลุดหรือเชื่อมต่อไม่สำเร็จ ล้างคำขอที่ค้างและเริ่มค้นหาใหม่โดยไม่ต้องหยุดเครื่องที่ยังเปิด session อยู่ มีการหน่วงก่อนลองใหม่และข้อความภาษาไทยบอกวิธีแก้
- แชตเรียงตามลำดับบันทึก SQLite ของเครื่องนี้ เก็บ timestamp ต้นทางไว้ แต่ข้อความใหม่แสดงเวลาเครื่องนี้บันทึก/รับ ไม่ใช้เวลาของโทรศัพท์อีกฝั่งจัดลำดับ
- เมื่อเวลาสองเครื่องต่างกันเกิน 5 นาที มีคำเตือนและปุ่มเปิดการตั้งค่าวันเวลา ควรเปิดวันและเวลาอัตโนมัติทั้งสองเครื่อง แอปไม่มีแหล่งเวลาอ้างอิงออฟไลน์ที่รับประกันว่าเป็นเวลาจริง ข้อความเก่าไม่มีเวลารับที่ย้อนสร้างได้
- เส้นทางตรงถูกบันทึกทั้งเมื่อรับข้อความและเมื่อผู้ส่งได้รับ ACK ข้อความที่ไม่มีข้อมูลเส้นทางไม่แสดงป้ายไม่ทราบเส้นทาง
- ข้อความ pending และ sent อยู่กลุ่มรอการยืนยัน delivered หมายถึงปลายทางบันทึกแล้ว ไม่ใช่ผู้รับอ่านแล้ว และไม่มีการอ้างว่าซิงก์ cloud จาก ACK
- ข้อความ/สื่อใหม่แจ้งด้วย MaterialBanner เมื่อเปิดแอป หรือ Android notification เมื่ออยู่เบื้องหลัง ไม่มี snackbar สำหรับเหตุการณ์เดียวกัน ข้อความซ้ำจาก retry ไม่แจ้งซ้ำ
- SOS แจ้งเตือนเฉพาะเมื่อเปิดโหมดกู้ภัยและอนุญาตการแจ้งเตือน เครื่องทั่วไปยังรับสถานะและดูรายการ SOS ได้ แบนเนอร์มีประเภทเหตุ จำนวนคน รายละเอียด และปุ่มดู SOS/แชต
- Android notification มีข้อมูลคู่สนทนาและ SOS สำหรับเปิดรายละเอียด/แชตทั้งกรณีแอปเปิดอยู่และกู้หน้าจอใหม่ ใช้ revision เดิมไม่แจ้งซ้ำทุก heartbeat
- พิกัดและแผนภาพพิกัดใช้ได้ออฟไลน์ ส่วนถนน/เส้นทางยังอาศัยแอปแผนที่และข้อมูลพื้นที่ที่ดาวน์โหลดไว้ล่วงหน้า ไม่รับประกันการใช้ offline จากการเคยเปิดออนไลน์เพียงครั้งเดียว

## ทดสอบบนโทรศัพท์จริงหลังติดตั้ง APK ใหม่ทั้งสองเครื่อง

### แท็บข้อความ

- แสดงจำนวนข้อความใหม่รวม จำนวนการสนทนาที่ยังไม่ได้อ่าน และตัวนับในแต่ละแชต พร้อมตัวอย่างข้อความล่าสุด (สื่อแสดงเป็นรูปภาพ/วิดีโอ)
- เปิดแชตปกติขณะอยู่หน้าแอปแล้วจึงบันทึกว่าอ่านถึงข้อความที่แสดง ไม่ล้างจำนวนอ่านจากการรับ ACK การอยู่เบื้องหลัง หรือการเปิดหน้าค้นหา/กรอง
- ตัวนับไม่เพิ่มจากข้อความ retry ซ้ำและเก็บสถานะอ่านใน SQLite ข้อมูลเก่าก่อนเพิ่มฟังก์ชันนี้ถือเป็นประวัติเดิม เนื่องจากเดิมไม่ได้บันทึกว่าผู้ใช้เคยอ่านถึงจุดใด
- บทบาทผู้ใช้ทั่วไป/หน่วยกู้ภัยอิงสถานะที่คู่สนทนาประกาศ ข้อมูลที่เก่าแสดง “สถานะล่าสุด” ไม่มีข้อมูลแสดง “ยังไม่ทราบบทบาท”
- ลบปุ่มทดลองสื่อจำลองในแท็บข้อความและทางเข้าจำลองจากปุ่มแนบสื่อ รวมถึงแถบ “เชื่อมต่อแล้ว • ถึงปลายทาง = บันทึกบนเครื่องรับแล้ว”
- ตรวจเพิ่ม: B อยู่แท็บข้อความ ให้ A ส่งสองข้อความ ดูยอดใหม่/ตัวอย่าง เปิดแชต B แล้วกลับออกมายอดต้องหาย ปิดเปิดแอปแล้วยังจำสถานะอ่านได้ เปลี่ยนโหมดกู้ภัย A แล้วตรวจบทบาทที่ B หลังได้รับสถานะใหม่

1. เปิด Guest ตั้งชื่อเครื่องต่างกัน เปิด Bluetooth/Wi-Fi และเริ่ม session ทั้งคู่ ตรวจว่าเชื่อมกันได้
2. ส่ง A1 → B1 → A2 โดยตั้งเวลาเครื่องหนึ่งต่างกัน ตรวจลำดับและคำเตือนเวลา จากนั้นเปิดเวลาอัตโนมัติทั้งสองเครื่อง
3. ส่งข้อความและดูแบนเนอร์ กดเปิดแชต ตรวจว่าไม่มี snackbar ซ้ำและไม่มีป้ายไม่ทราบเส้นทางบนข้อความตรง
4. หยุด B ส่งข้อความค้างจาก A เริ่ม B อีกครั้งโดยไม่หยุด A ตรวจ reconnect และ ACK หลังส่งซ้ำ
5. ปิดโหมดกู้ภัย B แล้วให้ A ส่ง SOS: สถานะเข้ารายการแต่ไม่มี popup เปิดโหมดกู้ภัยแล้วให้ A อัปเดต SOS: แสดงแบนเนอร์เดียว ดูรายละเอียด/พิกัดและเข้าแชตได้
6. สลับ B ไปแอปอื่น ส่งข้อความ/SOS จาก A แล้วแตะ Android notification หรือปุ่มดู SOS ตรวจหน้าเปิดถูกคน
7. ไม่มีเน็ต: ดูและคัดลอกพิกัดได้ ทดสอบแอปแผนที่ในพื้นที่ที่ดาวน์โหลด offline ไว้แล้ว

## การตรวจอัตโนมัติ

ชุดทดสอบที่เกี่ยวข้องครอบคลุมแชตเวลาคลาดเคลื่อน ACK/เส้นทาง ข้อความซ้ำ คิวส่ง การอัปเกรดข้อมูลเดิม หน้าแผนที่ สื่อ และ relay เพิ่ม regression สำหรับ reconnect โดยไม่รีสตาร์ตอีกฝั่งและการเลือกผู้เริ่มเชื่อมต่อ

การผ่าน unit/widget tests ไม่ใช่ผลผ่านวิทยุ Nearby และการแตะ Android notification บนโทรศัพท์จริง ต้องยืนยันตามรายการด้านบน

## สร้าง APK

PowerShell ต้องส่งรายการแพลตฟอร์มเป็น string เดียว:

```powershell
.\tool\flutter.ps1 build apk --debug '--target-platform=android-arm,android-arm64,android-x64' --dart-define-from-file=config/supabase.local.json
```

ใช้ APK เดียวกันทั้งสองเครื่อง ติดตั้งอัปเดตได้โดยไม่ล้างข้อมูลเดิม
