# ความสามารถจากโค้ด RescueLink ปัจจุบัน — 18 ตุลาคม 2569

ตรวจ working tree ปัจจุบัน รวมส่วนแชตและ Auth ที่เปลี่ยนหลังรายงานเดิม การมี implementation ไม่ใช่ผลทดสอบวิทยุหรือ Cloud จริง

## ความสามารถ

| ส่วน | ทำอะไรได้ | เงื่อนไข/ข้อจำกัด |
|---|---|---|
| บัญชี | สมัครสมาชิก ยืนยันอีเมล ส่งอีเมลยืนยันซ้ำ Login/Logout ลืมและตั้งรหัสผ่านใหม่ จำ session | สมัคร/Login ใหม่ต้องออนไลน์; รุ่นนี้ไม่มีทางเข้า SOS แบบ Guest |
| ข้อมูลสมาชิก | ดู/แก้ชื่อ ลบบัญชีด้วยรหัสผ่าน แยกข้อมูล local ตามบัญชี | การทำรายการ Cloud ต้องออนไลน์ |
| ข้อมูลสุขภาพ | ข้อมูลส่วนตัว กรุ๊ปเลือด โรคประจำตัว แพ้ยา ยา ผู้ติดต่อฉุกเฉิน และความยินยอม พร้อม cache/คิวข้อมูลส่วนตัว | ไม่ได้ส่งข้อมูลสุขภาพทั้งหมดใน SOS อัตโนมัติ |
| ใกล้ฉัน | ประกาศตัว ค้นหา เชื่อมต่อด้วยมือหรืออัตโนมัติ แสดงสถานะผู้ใช้และเส้นทาง | Nearby ใช้บน Android; ต้องเปิดวิทยุและอนุญาตสิทธิ์ ไม่มี router/hotspot ก็สื่อสารได้เมื่อเชื่อมสำเร็จ |
| แชต | ข้อความตัวอักษร ประวัติในเครื่อง จำนวนยังไม่อ่าน ค้นหาคู่สนทนา/ข้อความ และตัวกรอง | ส่งผ่าน Nearby; Cloud เป็นสำรองประวัติส่วนตัว ไม่ใช่ส่งแชตออนไลน์ข้ามระยะ |
| สื่อ | เลือก ส่ง รับ เปิดรูป เล่นวิดีโอ ตรวจขนาด/SHA-256 และ ACK หลังรับครบ | ส่งตรงไม่เกิน 50 MiB; ผ่านเครื่องกลางไม่เกิน 5 MiB |
| SOS | สร้างเหตุ ระบุประเภท จำนวนคน รายละเอียด เปิด/ปิด/แก้ไขสถานะ และประวัติเหตุ; สถานะแดง แตะเข้าแชต | อีกเครื่องต้องค้นพบ/เชื่อมต่อก่อนเห็นสถานะ; เหตุมีอายุ 24 ชั่วโมงจากการอัปเดต |
| พิกัด SOS | อ่าน GPS เก็บพิกัดล่าสุดใน SQLite ของบัญชี ใช้ cache เมื่ออ่านใหม่ไม่ได้ และก่อนยืนยันส่งเมื่อฟอร์มไม่มีพิกัด | cache นี้เกิดจากการอ่าน GPS สำเร็จในหน้า SOS; คง timestamp/ความแม่นยำเดิม แสดงว่าเป็นพิกัดเก่า; ถ้าไม่มี cache ส่งแบบไม่มีพิกัดได้ |
| กู้ภัย | เปิด/ปิด Rescue สีน้ำเงิน ดูรายละเอียด SOS และพิกัด ติดต่อผู้แจ้งผ่านแชต | แสดงสถานะเปิด/ยกเลิก/หมดอายุจาก SOS ของผู้แจ้ง ไม่มีระบบรับเคสหรือติดตามงานช่วยเหลือ (ปรับขอบเขต 19 ต.ค. 2569) |
| Relay | ข้อความ SOS สื่อ และ ACK ผ่าน A–B–C พร้อมคิวถาวร กันซ้ำ และจำกัดเส้นทาง | สูงสุด 8 hops ต้องมีเส้นทางที่ใช้ได้; ต้องทดสอบ 3 เครื่องโดยปิดลิงก์ A–C เพื่อพิสูจน์ |
| คิวส่ง | บันทึกก่อนส่ง รอเชื่อมต่อ ลองใหม่ และแยกผลถึงเครื่องรับจากผล Cloud | ACK ไม่ใช่อ่านแล้วหรือเจ้าหน้าที่รับงาน |
| Cloud Sync | ซิงก์ประวัติข้อความ/SOS จัดการ conflict และสำรองสื่ออัตโนมัติจากไฟล์ที่บันทึกครบ | รอบประมาณ 15 วินาทีระหว่าง runtime และเมื่อกลับเข้าแอป; ไม่รับประกันเมื่อ force-stop |
| กู้ประวัติ Cloud | ดึง chat_records กลับมาแสดงในรายการแชตและห้องสนทนา รวมการรู้จัก radio ID ของอุปกรณ์ในบัญชี | การจัดเจ้าของข้อความเก่ายังมี heuristic จากชื่อ/จำนวนข้อความ ดูข้อสังเกตด้านล่าง |
| พิกัดและแผนภาพ | ดูตัวเลข อายุ ความแม่นยำ แผนภาพพิกัด คัดลอก และเปิดในแอปแผนที่ภายนอก | แผนภาพ local ไม่มีถนนหรือแผนที่พื้นที่ออฟไลน์; แอปแผนที่ภายนอกต้องมีเน็ตหรือดาวน์โหลดพื้นที่ไว้ |
| แจ้งเตือนและตั้งค่า | แจ้งในแอป/Android แตะเปิดสนทนา คง session ด้วย foreground service สว่าง/มืด/ตามระบบ ไทย/อังกฤษ | การแปลยังไม่ครบทุกข้อความ; force-stop ไม่เริ่ม session ใหม่เอง |

## จุดที่ยังต้องระวัง

1. **เริ่มใช้งานออฟไลน์ครั้งแรกไม่ได้:** `main.dart` ให้ไป Onboarding/Login เมื่อไม่มี session การจำ session ช่วยเฉพาะบัญชีที่เคยยืนยันและ Login สำเร็จ
2. **การกู้แชตอาจจับเจ้าของผิด:** `MessageService._mergeCloudHistory()` ใช้ชื่อผู้ส่งและ ID ที่พบมากที่สุดเป็น fallback นอกเหนือจาก radio IDs ที่บันทึกไว้ ชื่อซ้ำ เปลี่ยนชื่อ หรือประวัติหลายอุปกรณ์จึงอาจทำให้ข้อความถูกจัดเป็นของตนผิดฝั่ง ไม่พบ tests เจาะจง heuristic ใหม่นี้ในการค้นรอบนี้ ควรยึด identity ที่ยืนยันได้และมี mapping ชัดเจน
3. **บริบทบัญชีระหว่าง async:** ส่วนอ่าน `account_devices` ใน Auth/Chat Cloud เขียน `myRadioIds` ผ่าน `LocalDatabaseService.instance` จึงควรทดสอบการสลับบัญชีระหว่าง request และผูกกับ database handle ของบัญชีที่เริ่มงาน
4. **ข้อมูล Cloud ไม่ใช่การส่งถึงเพื่อน:** การดึง `chat_records` ใช้ `owner_id` ของตน ไม่ได้ subscribe ห้องสนทนาออนไลน์กับผู้ใช้อื่น
5. **หลักฐานเครื่องจริงยังจำเป็น:** tests ใช้ fake transport และฐานข้อมูลทดสอบ ไม่แทน Bluetooth/Wi-Fi, GPS, จอดับ, OEM battery policy หรือการส่งสื่อครบจริง
