# ประวัติข้อความ CRUD และ Cloud Sync — 2026-10-08

ข้อความตัวอักษรที่ส่งและรับผ่าน Nearby บันทึกใน SQLite พร้อมสำเนาประวัติและคำสั่งซิงก์ในธุรกรรมเดียวกัน ประวัติเดิมในฐานข้อมูลของบัญชีจะเข้าคิวตอนอัปเกรด schema จาก version 8 เป็น 9

ผู้ใช้ที่เข้าสู่ระบบจะซิงก์ประวัติกับ Supabase `public.chat_records` โดยแยกข้อมูลตาม `owner_id` Guest เก็บข้อมูลในเครื่องเท่านั้น แอปลองซิงก์ทุก 15 วินาทีขณะเปิดแอป เมื่อกลับมาที่แอป และเมื่อกดซิงก์เอง ไม่มีการรับประกันการซิงก์ขณะแอปปิดหรือถูก OS หยุด

## วิธีใช้

1. เข้าสู่ระบบ เปิดแชตและส่ง/รับข้อความ หากไม่มีอินเทอร์เน็ต ประวัติและคิวจะอยู่ในเครื่อง
2. เปิด **ประวัติข้อความ / Cloud** จากไอคอน Cloud ในหน้าแชตหรือหน้าข้อมูลสมาชิก (บนเว็บเข้าจากหน้าข้อมูลสมาชิก)
3. เชื่อมต่ออินเทอร์เน็ต รอรอบซิงก์หรือกดไอคอนซิงก์ จำนวนค้างซิงก์จะลดลงเมื่อ Cloud ยืนยัน
4. กด **แก้ไขประวัติ** หรือ **ลบประวัติ** การเปลี่ยนแปลงเข้าคิวถาวรและซิงก์ในรอบถัดไป
5. หากมีข้อมูลขัดแย้ง หน้าประวัติแสดงข้อความจาก Cloud ให้เลือก **ใช้ของฉัน** หรือ **ใช้ Cloud** ข้อมูลที่ Cloud ลบแล้วไม่สามารถคืนด้วยสำเนาเก่า

## ขอบเขต

- CRUD เป็นประวัติส่วนตัวของบัญชี ทั้งข้อความส่งและรับ ไม่เปลี่ยนแพ็กเก็ตที่ส่งผ่าน Nearby และไม่แก้ไข/ลบข้อความจากเครื่องผู้รับ
- Cloud เป็นการสำรองและกู้ประวัติของบัญชี ไม่ใช่การส่งข้อความถึงบัญชีคู่สนทนาผ่านอินเทอร์เน็ต
- ประวัติที่กู้จาก Cloud แสดงในหน้าประวัติ ไม่เข้าคิวส่ง Nearby ซ้ำ
- สถานะ Cloud แยกจาก ACK ของ Nearby การอัปโหลดสำเร็จไม่ได้หมายถึงผู้รับได้รับข้อความ
- ครอบคลุมข้อความตัวอักษรเท่านั้น ไฟล์สื่อใช้ระบบ Media Upload เดิม
- การลบใช้ tombstone บน Cloud เพื่อป้องกันเครื่องออฟไลน์นำประวัติกลับมา

## ความคงทนและสิทธิ์

`chat_queue` เก็บ operation UUID และ base version การลองส่งซ้ำหลังคำตอบสูญหายได้ผลเดิมด้วย receipt ฝั่งเซิร์ฟเวอร์ การแก้ไขพร้อมกันใช้ compare-and-swap และหยุดเฉพาะประวัติที่ขัดแย้ง RLS จำกัดการอ่านเฉพาะเจ้าของ การเขียนผ่าน RPC `sync_chat` ที่ตรวจ auth.uid() ไม่มีสิทธิ์เขียนตารางโดยตรงจาก client

ตาราง `sync_private.chat_receipts` เปิด RLS และไม่ให้ client อ่าน/เขียนโดยตรง ไม่มี policy โดยตั้งใจ เพราะฟังก์ชันภายในที่ตรวจเจ้าของเท่านั้นเป็นผู้เข้าถึง Supabase advisor จึงรายงาน informational `rls_enabled_no_policy` สำหรับตารางนี้
