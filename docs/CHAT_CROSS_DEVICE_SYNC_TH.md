# การกู้คืนแชทเมื่อเข้าสู่ระบบอีกเครื่อง

การอัปเดตนี้เก็บฝั่งเจ้าของข้อความ (`archiveIdentity`) และชื่อผู้ติดต่อไว้กับประวัติของบัญชี โดยใช้รหัสตัวตนของเครื่องที่ผูกบัญชี ไม่เดาจากชื่อหรือจำนวนข้อความ เครื่องใหม่จึงแปลงข้อความฝั่งตนเองมาเป็นตัวตนปัจจุบันได้ แม้เปลี่ยนชื่อหรือมีผู้ใช้ชื่อซ้ำกัน

ประวัติครอบคลุมข้อความ รูป/วิดีโอ และข้อความ SOS ในห้องแชท ข้อมูลเดิมใน SQLite จะเข้าคิวสำรองเมื่ออัปเดตฐานข้อมูลเป็นรุ่น 10 การกู้คืนไม่เพิ่มข้อความลงคิวส่ง Nearby และไม่ส่งข้อความเก่าซ้ำ ไฟล์ที่ดาวน์โหลดจะตรวจขนาดและ SHA-256 ก่อนบันทึก แยกโฟลเดอร์ตามฐานข้อมูลบัญชี และลองใหม่อัตโนมัติหากดาวน์โหลดไม่ครบ

หน้าแชทแสดงสถานะกำลังกู้คืนหรือข้อผิดพลาดพร้อมปุ่มลองซิงก์ใหม่ หน้าประวัติ SOS รีเฟรชเมื่อข้อมูล Cloud เปลี่ยน การแก้ไขและลบประวัติจากอีกเครื่องสะท้อนในรายการที่แสดง โดยยังคงแยกประวัติออกจากแพ็กเก็ตส่งผ่าน Nearby

## เปิดใช้งาน

1. รัน `supabase/migrations/20261026090000_complete_chat_archive.sql` ใน Supabase ของโปรเจ็กต์ ฟังก์ชันเดิมจะรับประวัติชนิด `media` และ `sos` เพิ่ม พร้อมตรวจว่า `archiveIdentity` ตรงกับผู้ส่งหรือผู้รับ ข้อมูลเดิมและสิทธิ์เจ้าของบัญชีคงอยู่
2. ติดตั้งแอปที่มีโค้ดชุดนี้บนเครื่องเดิม เชื่อมต่ออินเทอร์เน็ตและเข้าสู่ระบบบัญชีที่มีประวัติ รอข้อความและไฟล์สื่ออัปโหลดสำเร็จก่อนเปลี่ยนเครื่อง
3. ติดตั้งแอปชุดเดียวกันบนเครื่องใหม่ แล้วเข้าสู่ระบบบัญชีเดิมขณะมีอินเทอร์เน็ต ประวัติจะดึงอัตโนมัติ และไฟล์จะทยอยกู้คืน

การเข้าสู่ระบบบัญชีเดิมไม่ย้ายข้อมูล Guest และไม่สามารถกู้คืนรายการที่ยังไม่เคยขึ้น Cloud หลังสูญเสียเครื่องเดิมได้ ประวัติเก่าที่ไม่มีข้อมูลฝั่งเจ้าของใช้ `account_devices` ของบัญชีเพื่อระบุเครื่องเดิม จึงควรเปิดแอปเวอร์ชันใหม่นี้บนเครื่องเดิมเพื่อเติมข้อมูลก่อนย้ายเครื่อง

## การตรวจสอบ

`test/chat_cross_device_test.dart` ใช้ SQLite สองฐานแทนสองเครื่องและ Cloud จำลอง ตรวจประวัติ 206 ข้อความหลายห้อง ชื่อซ้ำ การเปลี่ยนชื่อ ประวัติที่มีแต่ข้อความรับเข้า การแก้ไข/ลบจากอีกเครื่อง ประวัติรูปและ SOS การปฏิเสธไฟล์เสียและลองใหม่ การไม่ส่งแพ็กเก็ตเก่าซ้ำ การอัปเกรดฐานข้อมูล และการคงเนื้อหาคิวเดิมเมื่อคำตอบอัปโหลดสูญหาย

`supabase/tests/chat_sync.sql` ตรวจฟังก์ชันฝั่งเซิร์ฟเวอร์และการแยกเจ้าของบัญชี โดยต้องรันหลัง migration บนฐานข้อมูลทดสอบ สคริปต์ใช้ transaction และ rollback

## สถานะวันที่ 27 ตุลาคม 2569

นำ migration ขึ้น Supabase โปรเจ็กต์ `yrpqhupqbzymesknalnq` สำเร็จแล้วผ่าน SQL Editor โดยเทียบฟังก์ชันเดิมกับไฟล์ในโปรเจ็กต์ก่อนเปลี่ยน และบันทึกฟังก์ชันย้อนกลับไว้ที่ `output/chat-sync-deployment/rollback.sql`

ตรวจบนเซิร์ฟเวอร์จริงผ่านแล้ว: บันทึกประวัติชนิดข้อความ/สื่อ/SOS, รหัสเจ้าของข้อความ, การส่ง operation เดิมซ้ำ, ตัวตนสองเครื่องของบัญชีเดียวกัน, การแยกข้อมูลคนละบัญชี และการปฏิเสธผู้ที่ไม่ได้ล็อกอิน ข้อมูลสังเคราะห์ทั้งหมดในชุดตรวจนี้ถูก rollback หลักฐานอยู่ใน `output/chat-sync-deployment/verification.json` และสคริปต์อยู่ใน `output/chat-sync-deployment/server-checks.sql`

สร้าง APK release สำเร็จที่ `build/app/outputs/flutter-apk/app-release.apk` โดยใช้การตั้งค่า Supabase ของโปรเจ็กต์เดิม ให้ติดตั้งทับแอปเดิมบนทั้งสองเครื่อง แล้วรอเครื่องเดิมสำรองข้อความและสื่อขึ้น Cloud สำเร็จก่อนตรวจประวัติบนเครื่องใหม่

ชุดทดสอบสองไคลเอนต์จริง `test/chat_cross_device_live_test.dart` เตรียมไว้แล้ว แต่ยังทดสอบขั้นตอนล็อกอินจนจบไม่ได้: บัญชีใน `config/test-account.local.json` ถูกปฏิเสธด้วย invalid credentials ชุดนี้เปิดใช้เฉพาะเมื่อระบุ `--dart-define=RUN_LIVE_CHAT=true` ไม่ได้เปลี่ยนรหัสผ่านบัญชีทดสอบ การทดสอบด้วยโทรศัพท์จริงสองเครื่องยังต้องตรวจแยกจากผลจำลองและผล SQL บนเซิร์ฟเวอร์
