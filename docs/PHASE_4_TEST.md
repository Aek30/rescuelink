# Phase 4 — SOS / Rescue / Map acceptance

## ผลติดตาม: Huawei P30 / แจ้งเตือน / เริ่มอัตโนมัติ

ข้อมูลเพิ่มเติม: ผู้ใช้ยืนยัน P30 หา “ตำแหน่งของฉัน” ในแอปแผนที่ตอนออนไลน์ได้ถูกต้อง จึงเพิ่ม Google FusedLocationProviderClient แบบ optional พร้อม cancellation ควบคู่ Android GPS/network ใช้เมื่อ Play Services พร้อมเท่านั้น ช่องทาง Android ยังทำงานได้ถ้าฝั่ง Google ใช้ไม่ได้ ยอมรับพิกัดสดไม่เกิน 15 วินาทีและคืนเวลา/ความแม่นยำจริง เส้นทาง fused ถูกยกเลิกเมื่อได้ผลจากช่องทางใด หมดเวลา หรือออกจากแอป ทั้งนี้ผลออนไลน์ไม่ยืนยันการจับ GPS ออฟไลน์ของเครื่อง

ผู้ใช้ยืนยันรุ่น Huawei P30 และรายงาน Samsung S20 อ่าน GPS ได้ ส่วน P30 ยังหมดเวลา แม้อยู่บริเวณเดียวกัน; กดเริ่มอัตโนมัติทั้งสองเครื่องพบ Advertising start failed / PlatformException (ยังไม่ได้เลขรหัสเต็ม) ส่วนการทดสอบอื่นผู้ใช้รายงานว่าใช้งานได้ปกติ

- เอา SOS SnackBar ด้านล่างออกตามคำขอ คง Android notification ด้านบนและการ์ด/ตัวนับสถานะ
- รวมคำสั่งเริ่มซ้อนกันเป็นงานเดียว และ stop advertiser/discovery ที่อาจค้างก่อนเริ่ม native รอบใหม่ ไม่ตัด endpoint ที่เชื่อมต่ออยู่ ยังต้องกดเริ่มอัตโนมัติทั้งสองเครื่อง ไม่ใช่กดเพียงเครื่องเดียวเมื่ออีกเครื่องยังไม่ได้เปิดโหมดใด
- GPS รับ last-known เฉพาะพิกัดสดอายุไม่เกิน 15 วินาทีโดยคงเวลาจริง ลองแต่ละ provider แยกกัน และใช้เวลาบันทึกตรวจอายุเมื่อ provider ไม่มี monotonic timestamp ไม่ยอมรับพิกัดเก่าเป็นปัจจุบัน
- เพิ่มรายละเอียด timeout: GPS เปิดหรือไม่ จำนวนดาวเทียมที่พบ/ใช้คำนวณ และจำนวนพิกัดที่ระบบคืน เพื่อแยกไม่พบดาวเทียมออกจากกรณีส่งพิกัดกลับแต่ถูกคัดออก; จำนวนไม่ทราบไม่ได้หมายถึงศูนย์
- ยังไม่ยืนยัน root cause หรือการแก้สำเร็จบน P30 ต้องลอง “ตำแหน่งของฉัน” ในแอปแผนที่เมื่อออนไลน์ และส่งรายละเอียด timeout/รหัส Nearby จากรุ่นล่าสุด

ทดสอบซ้ำ: เริ่มอัตโนมัติทั้งสองเครื่องหลัง STOP, ส่ง SOS ให้มีเฉพาะแจ้งเตือนด้านบน, อ่าน GPS บน P30 แล้วเก็บข้อความวินิจฉัยหากยังหมดเวลา ไม่ต้องทดสอบ flow ที่ผู้ใช้ยืนยันผ่านซ้ำทุกข้อ เว้นแต่พบการถดถอย

## GPS timeout บน Huawei (ผู้ใช้ระบุ Huawei 30)

ผู้ใช้รายงาน S25 อ่านตำแหน่งได้ แต่ Huawei แสดง TimeoutException หลังรอ getLocation เดิม 25 วินาที ยังไม่ยืนยันรุ่นย่อย/สถานะ Google Services และไม่สรุปว่าเป็นสาเหตุจากยี่ห้อ

รุ่นแก้ไขใช้ Android LocationManager โดยตรง (GPS_PROVIDER และ NETWORK_PROVIDER ที่เปิดอยู่) ตาม [Android API](https://developer.android.com/reference/android/location/LocationManager) ไม่เรียก fused-location API ของ Google/HMS ในขั้นตอนอ่านพิกัด รอ native สูงสุด 60 วินาทีและมี Dart watchdog 65 วินาที ยกเลิก listener เมื่อได้ผล/หมดเวลา/ออกจากแอป ไม่ใช้ last-known fix เก่ามาแสดงเป็นข้อมูลสด รับ native fix อายุไม่เกิน 15 วินาทีโดยวัดด้วย monotonic clock และคงเวลา/ความแม่นยำจริง

เส้นทางอ่านตำแหน่งใหม่นี้ไม่ได้เปลี่ยนข้อกำหนด Google Play services ของ Nearby Connections และไม่ได้เพิ่มข้อมูลแผนที่ออฟไลน์

ทดสอบหลังติดตั้ง APK ใหม่ทั้ง Huawei และ S25:

1. เปิดตำแหน่ง อนุญาตตำแหน่งแบบแม่นยำให้ RescueLink ปิดโหมดประหยัดพลังงานชั่วคราวและอยู่กลางแจ้ง
2. กดอ่าน GPS เปิดหน้านี้ค้างไว้สูงสุด 60 วินาที ตรวจพิกัด เวลาและความแม่นยำ จากนั้นอัปเดต SOS ให้เครื่องรับตรวจพิกัดตรงกัน
3. ทำซ้ำโดยปิด mobile data/ไม่ต่อเครือข่าย Wi-Fi ที่มีอินเทอร์เน็ต (คง radio สำหรับ Nearby) หากยัง timeout ให้บันทึกรุ่นย่อย/Android และการอ่านตำแหน่งจากแอปอื่นในบริเวณเดียวกัน
4. ปิดบริการตำแหน่งหรือปฏิเสธสิทธิ์ ต้องได้คำแนะนำภาษาไทย; timeout ต้องไม่มีข้อความ Future not completed และกดอ่านใหม่ได้
5. ระหว่างอ่านกด Home แล้วกลับมา ต้องแจ้งยกเลิกและอ่านใหม่ได้ โดยยังส่ง SOS ไม่แนบพิกัดได้

ผลบน Huawei/S25 ของรุ่นแก้ไขยังรอยืนยัน Tests จำลอง method channel ไม่ใช่การทดสอบเสาอากาศ GPS จริง

## รุ่นแก้ไขตามผลทดสอบผู้ใช้

ผู้ใช้รายงานว่าเปิดแผนที่/พักแอป/ดับหน้าจอแล้ว Nearby หลุด, แอปแผนที่เปิดแต่ไม่มีภาพหรือหมุด, และตัวนับ SOS ไม่แสดงสถานะประกาศทันที

รุ่นแก้ไขเพิ่ม connectedDevice foreground service พร้อม notification และ partial wake lock เพื่อไม่เรียก STOP เมื่อ paused ระหว่าง session ที่เริ่มแล้ว; STOP ยังคืนทรัพยากรครบ ไม่มีการ restart หลัง force-stop/process death และการปัด task ทิ้งทำให้ service หยุด ต้องเปิดแอปเริ่มใหม่ ใช้พลังงานเพิ่มระหว่าง session

เพิ่มโหมดค้นหา/เชื่อมต่ออัตโนมัติที่ผู้ใช้กดเริ่มทั้งสองเครื่อง ส่งคำขอเชื่อมต่อเป็นรอบและค้นหาต่อหลังพบเครื่องแรก ยังต้องเชื่อมต่อระดับ Nearby สำเร็จก่อนส่งข้อมูลได้ ยังไม่ใช่ multi-hop

ย้ายสถานะขึ้นด้านบน แก้ตัวนับให้นับ fresh presence และแจ้ง SOS แรก/อัปเดต revision ในแอปกับ Android notification (ต้องอนุญาต notification; ระบบตั้งค่าปิดเสียงได้) ไม่แจ้งซ้ำตาม heartbeat

กรณีแผนที่เปิดแต่ไม่มีภาพ/หมุดยังไม่ยืนยันสาเหตุบนอุปกรณ์: ให้ตรวจพิกัดเดิมตอนออนไลน์และดาวน์โหลดพื้นที่ในแอปแผนที่ก่อนออฟไลน์ เพิ่มปุ่มคัดลอกพิกัดแล้ว ไม่ได้เพิ่มข้อมูลแผนที่ออฟไลน์ภายใน RescueLink

### ทดสอบซ้ำด้วย APK รุ่นแก้ไขทั้งสองเครื่อง

1. กดเริ่มรับส่ง SOS / เชื่อมต่ออัตโนมัติทั้งสองเครื่อง อนุญาตสิทธิ์ที่ขอ ตรวจว่าเชื่อมต่อโดยไม่กด Connect ทีละรายการ
2. A เปิด SOS โดยไม่เลือกผู้รับ: B เห็นตัวนับ/สถานะด้านบนและข้อความแจ้งโดยไม่เปิดหน้า SOS; รอ 20 วินาทีต้องไม่แจ้งซ้ำจาก heartbeat
3. A อัปเดต SOS: B แจ้งการอัปเดตหนึ่งครั้ง; ปิด SOS แล้วตัวนับลดลง
4. กด Home/เปิดแผนที่/ดับหน้าจอ B อย่างน้อย 2 นาที ให้ A ส่ง SOS/แชต ตรวจว่า B ยังได้รับ กลับแอปแล้วยังเห็นการเชื่อมต่อ (ต้องมี notification บริการทำงาน)
5. ขณะ B ดับหน้าจอ ส่ง SOS ใหม่จาก A ตรวจ Android notification ถ้าอนุญาตแล้ว; ตรวจโหมดประหยัดแบตเตอรี่/OEM บนเครื่องจริงด้วย
6. กด STOP: notification บริการหายและการเชื่อมต่อหยุด ปัด task ทิ้ง/force-stop ต้องเริ่มใหม่ ไม่รับรองว่าเชื่อมต่อค้าง
7. เปิดพิกัดเดิมออนไลน์ก่อน แล้วดาวน์โหลดแผนที่พื้นที่และลองออฟไลน์ เปรียบเทียบหมุดกับตัวเลขพิกัด; คัดลอกพิกัดได้แม้ไม่มีข้อมูลแผนที่

ขั้นตอนรุ่นแรกด้านล่างเป็นประวัติ โดยข้อที่กำหนดว่าต้อง reconnect หลังเปิดแผนที่ถูกแทนด้วยข้อ 4 ด้านบน ผลรุ่นแก้ไขบนมือถือจริงยังรอยืนยัน

## ขอบเขต

- ประกาศ snapshot SOS (ข้อความ + GPS ที่อ่านครั้งล่าสุด) และ Rescue ให้ทุก peer ที่แนะนำตัวแล้วผ่าน Nearby โดยตรง ไม่ใช่ multi-hop หรือค้นหา/เชื่อมต่ออัตโนมัติ
- เปิด SOS ก่อนมีผู้รับได้; เมื่อเชื่อมต่อสำเร็จส่ง snapshot และส่งซ้ำทุก 5 วินาที ปิดโหมดแล้วส่งสถานะปิดซ้ำด้วย
- บันทึกโหมดของเราและสถานะ peer ใน SQLite settings เดิม ไม่ล้างประวัติ Phase 3
- sequence เพิ่มและบันทึกก่อนส่ง; รับเฉพาะผู้ส่งที่ตรงกับ endpoint และ receiver; ไม่รับ sequence ซ้ำ/ย้อนหลัง
- อายุสถานะใช้เวลารับของเครื่องเรา ไม่เชื่อเวลาของเครื่องส่ง; หลัง 30 วินาทีขึ้นสีเทาหมดอายุในรอบ refresh ถัดไป โดยยังอ่านข้อมูลเก่าได้
- GPS เป็น snapshot จากปุ่มอ่าน GPS ไม่ได้ติดตามสด; การเปิด SOS และ Rescue พร้อมกันแสดง SOS สีแดงเป็นหลักพร้อมข้อความว่าเปิด Rescue ด้วย
- ปุ่มแผนที่ใช้ Android ACTION_VIEW geo URI ตาม [Android documentation](https://developer.android.com/guide/components/google-maps-intents) ไม่เพิ่ม dependency หรือสิทธิ์ GPS ใหม่
