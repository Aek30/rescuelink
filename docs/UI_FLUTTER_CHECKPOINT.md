# UX/UI Flutter — checkpoint 2026-09-25

นำแนวทางจาก ui-preview มาใช้ในแอป Flutter โดยเก็บต้นแบบและ service เดิมไว้
เป็นการปรับหน้าตาและการนำทางแบบ native ไม่ใช่การฝังเว็บหรือรับรองว่าตรงทุกพิกเซล

## ผู้ใช้และโฟลว์

- ผู้ประสบภัย: เข้าแบบ Guest → ใกล้ฉัน → เชื่อมต่อ → SOS → กรอก/ยืนยัน → แก้ไขหรือยกเลิก
- หน่วยกู้ภัย: SOS / หน่วยช่วยเหลือ → เปิด Rescue → ดูสถานะผู้ประสบภัย → รายละเอียดเหตุ → แชต
- สนทนา: ข้อความ → เลือกคู่สนทนา → ส่งข้อความจริง → คิวส่ง → ส่งซ้ำ/รอ ACK
- กลับมาออนไลน์: ฉัน → บัญชีและซิงก์ (จำลอง) → เปิดอินเทอร์เน็ตจำลอง → บัญชีตัวอย่าง → ซิงก์/ลองใหม่
- สื่อ: ข้อความหรือปุ่มแนบในแชต → หน้าสื่อจำลอง → แนบรูป/วิดีโอตัวอย่าง → ค้างส่ง/ส่งแล้วจำลอง

## หน้าจอและขอบเขต

| หน้า | ระบบเดิมที่เชื่อมจริง | ส่วนจำลอง |
|---|---|---|
| ใกล้ฉัน | Nearby, อุปกรณ์เชื่อมต่อ, สถานะ SOS/Rescue | ไม่มีรายชื่อหรือระยะทางปลอม |
| สร้าง/แก้ไข SOS | แบบฟอร์ม, ยืนยัน, พิกัด, ยกเลิก, Rescue | ไม่มี |
| รายละเอียดเหตุ | ข้อมูลล่าสุดจาก presence, หมดอายุ, เปิดพิกัด, แชต | ไม่มี |
| ข้อความ | ข้อความ, SQLite, คิวและ ACK | รูป/วิดีโอเป็นตัวอย่าง ไม่เลือกไฟล์หรือเล่นวิดีโอจริง |
| คิวส่ง | pending/sent จาก MessageService และ retry | ลิงก์ไปทดลอง cloud sync |
| ฉัน | ชื่อเครื่อง, สิทธิ์, การเชื่อมต่อแบบละเอียด | บัญชี/คลาวด์ ไม่มีการขอรหัสผ่าน |

## ธีมและสถานะ

- พื้นครีม #FFF8F2, ปุ่มส้ม #FF9F5A, ตัวอักษรเข้ม, ฟอนต์ Noto Sans Thai จาก asset เดิม
- SOS สีแดง / Rescue สีน้ำเงิน พร้อมข้อความกำกับ
- มีหน้าว่าง, รอโหลด, ข้อผิดพลาดและคิวออฟไลน์
- โหมดจำลองมีป้ายชัดเจน ใช้ state ในหน้านั้น ไม่เขียนลง MessageService/SQLite และล้างเมื่อออก
- สถานะ DELIVERED คือบันทึกบนเครื่องผู้รับ ไม่ใช่การยืนยันรับช่วยเหลือหรือ cloud sync
