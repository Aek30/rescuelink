# ขอบเขตส่งงาน Off-Grid SOS & Nearby Share

อ้างอิงข้อกำหนดอาจารย์ที่ผู้ใช้ส่งวันที่ 2026-09-25 (กลุ่มไม่เกิน 5 คน) เอกสารนี้ใช้เสริมแผน Phase เดิม ไม่ถือว่าจบครบเพียงเพราะทำถึง Phase 5

## สถานะปัจจุบัน

- ทำแล้ว: Nearby แบบเชื่อมต่อโดยตรง, แชตข้อความ, SQLite/history, คิวส่งซ้ำและ ACK, SOS พร้อมพิกัด snapshot, อัปเดต/ยกเลิก SOS, เปิดแชตจาก SOS
- ผู้ใช้รายงานผ่านการทดสอบจริง 5 หัวข้อของ Phase 3; ไม่เหมารวมว่า multi-hop, media หรือ cloud ผ่านแล้ว
- Phase 4 พัฒนาแล้ว: ประกาศ SOS สีแดงและ Rescue สีน้ำเงินให้ทุกเครื่องที่เชื่อมต่อ ส่งซ้ำ/รองรับเครื่องใหม่/หมดอายุสถานะ และแตะเข้าแชตได้; ยังรอทดสอบบนมือถือจริง
- ปุ่มเปิดพิกัดในแอปแผนที่พร้อมอายุ/ความแม่นยำและกรณีเปิดไม่ได้พัฒนาแล้ว; ยังไม่มีแผนที่ออฟไลน์ในแอป
- มี enum synced แต่ยังไม่มีระบบ cloud sync จริง

## งานที่ต้องครบตามโจทย์

- [ ] ประกาศเปิด/ปิด SOS ให้เครื่องใกล้เคียงเห็นสีแดง พร้อมข้อความสั้นและพิกัดล่าสุด; รองรับเพื่อนที่เพิ่งเชื่อมต่อและการหมดอายุสถานะ ไม่รับประกันคำว่า “ทันที” ก่อนค้นพบ/เชื่อมต่อสำเร็จ
- [ ] ประกาศเปิด/ปิด Rescue ให้เครื่องอื่นเห็นสีน้ำเงิน และเปิดบทสนทนาจากสถานะได้
- [ ] Multi-hop A → B → C เมื่อ A ติดต่อ C โดยตรงไม่ได้: origin/destination, deduplication, TTL/hop limit, relay persistence, ACK กลับปลายทาง และทดสอบอย่างน้อย 3 เครื่อง
- [ ] ส่งรูปภาพและวิดีโอออฟไลน์ พร้อมจัดเก็บไฟล์/metadata, retry, ขนาดไฟล์และการส่งไม่ครบ
- [ ] ระบบสมาชิกเมื่อมีอินเทอร์เน็ต โดยไม่กีดกันฟังก์ชันฉุกเฉินออฟไลน์; กำหนดการเชื่อมบัญชีกับข้อมูลเดิมในเครื่อง
- [ ] Cloud storage และคิว sync เมื่อกลับมาออนไลน์ พร้อมป้องกันข้อมูลซ้ำ/จัดการ conflict และสิทธิ์เข้าถึงข้อมูล
- [ ] UI ค้างส่ง/ส่งแล้ว/ซิงก์แล้วจากผลจริง; แยก ACK บันทึกบนเครื่องรับออกจาก cloud sync และการตอบรับช่วยเหลือ
- [ ] Offline-first ครอบคลุมทุกฟีเจอร์หลัก รวมรายการคน/สถานะที่บันทึกไว้, สื่อและประวัติหลัง restart
- [ ] UX/UI ภาษาไทยให้ครบทุก flow, error/empty/loading states, ความชัดเจนของสถานะและการเข้าถึง
- [ ] ทดสอบรวมบนมือถือจริง, release APK, README, หลักฐานผลทดสอบ, ภาพหน้าจอและ demo

## งานตำแหน่งที่ผู้ใช้ย้ำให้ทำ

- [ ] ปุ่มเปิดตำแหน่ง SOS บนแอปแผนที่จากพิกัดที่ได้รับ
- [ ] พิจารณาแผนที่พร้อมหมุดในแอปและข้อมูลแผนที่ออฟไลน์ เพื่อให้เห็นบริเวณที่อยู่โดยไม่พึ่งอินเทอร์เน็ต
- [ ] แสดงอายุพิกัด ความแม่นยำ และกรณีไม่มี GPS/ไม่มีแอปแผนที่/ไม่มีข้อมูลแผนที่ในเครื่อง

การส่งตัวเลขพิกัดออฟไลน์มีแล้ว แต่ไม่เท่ากับมีแผนที่ออฟไลน์ งานแผนที่เป็นความต้องการเพิ่มของผู้ใช้ ไม่ใช่ข้อบังคับแผนที่แบบเจาะจงในข้อความโจทย์

## ลำดับทำต่อ

1. ปิดช่องว่าง SOS/Rescue status และปุ่มดูตำแหน่ง
2. Multi-hop และสื่อออฟไลน์
3. ระบบสมาชิกและ cloud sync
4. เก็บ offline-first และ UX/UI ก่อนทดสอบรุ่นสุดท้าย
5. ทดสอบ acceptance ตามโจทย์ทุกข้อและเตรียมส่งงาน

ประเมินคร่าว ๆ ณ วันที่บันทึก: ทำแล้วประมาณ 40–50%, เหลือประมาณ 50–60% ของงานพัฒนา/ตรวจสอบรวม ไม่ใช่น้ำหนักคะแนนจากอาจารย์ และไม่ใช่จำนวน Phase หารกัน
