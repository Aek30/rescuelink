# หน้าใกล้ฉัน: Normal / SOS / Rescue

วันที่ตรวจ: 9 ตุลาคม 2026

## ไฟล์ที่แก้สำหรับงานนี้

- `lib/screens/nearby_test_screen.dart`: แยกแผนที่ออกจากส่วนรายการอุปกรณ์ เรียงส่วนตาม `MessageService.mySos` และ `rescueMode`, Hero สีแดง/น้ำเงินและปุ่มปิดโหมด, เริ่มค้นหาหลังเปิดหน้าจอ, จัดการกลับจากหน้าขอสิทธิ์และการหยุดโดยผู้ใช้, เปิดแชต/รายละเอียด SOS จากอุปกรณ์จริง และแก้ Material ของการ์ดสิทธิ์
- `lib/services/nearby_service.dart`: เพิ่ม `startNearby()` สำหรับ Advertising + Discovery โดยไม่เปิด `autoConnect`; แชร์งานเริ่มที่กำลังทำอยู่ และค้นหาต่อหลังเชื่อมต่อด้วยมือ `startAutomatic()` เดิมยังใช้ได้สำหรับผู้เรียกเดิม
- `lib/services/message_service.dart`: สลับโหมดผ่านระบบ SOS เดิม ยกเลิก SOS และสร้าง revision/คิวเดิมก่อนเปิด Rescue; ปิด Rescue ก่อนบันทึก SOS; ป้องกันการเปลี่ยนโหมดชนกัน และแก้ค่าที่บันทึกเก่าหากเปิดสองโหมดพร้อมกัน
- `lib/services/permission_service.dart`: ตรวจสถานะ Wi-Fi เพิ่มจากสิทธิ์ Android, Bluetooth และบริการตำแหน่งเดิม
- `android/app/src/main/kotlin/com/rmutt/rescuelink/MainActivity.kt`: เพิ่มคำสั่งอ่านสถานะ Wi-Fi ใน MethodChannel เดิม ไม่ต้องติดตั้ง plugin เพิ่ม
- `lib/widgets/presence_list.dart`: เพิ่มตัวกรอง SOS ที่ยังมีผล / Rescue ที่มีสถานะใหม่, ข้อความเมื่อไม่มีข้อมูล, เปิดแชตเมื่อมีเส้นทางติดต่อจริง และยังดูรายละเอียดเหตุที่เก็บไว้ได้
- `lib/widgets/device_tile.dart`: แสดงบทบาทตามข้อมูลจริง สีแดง SOS / น้ำเงิน Rescue / ยังไม่ทราบสถานะ, ปุ่มแชตเมื่อเชื่อมต่อแล้ว, ดูรายละเอียด SOS และเมนูตัดการเชื่อมต่อ
- `test/nearby_modes_test.dart`: ตรวจโหมดของเครื่องเอง ลำดับส่วน ปุ่มปิดโหมด ธีมสว่าง/มืด และ lifecycle ระหว่างขอสิทธิ์
- `test/nearby_service_test.dart`: ตรวจค้นพบโดยไม่เชื่อมต่ออัตโนมัติ, เริ่มซ้ำไม่เรียก native ซ้ำ และค้นหาต่อหลังเชื่อมต่อ
- `test/message_service_test.dart`: ตรวจการสลับโหมด การยกเลิก SOS ในคิว และการคืนค่าหลังเปิดฐานข้อมูลใหม่; ปรับกรณีเก่าที่คาดว่าจะเปิดสองโหมดพร้อมกัน
- `test/phase_4_widgets_test.dart`: ตรวจว่าหน้าสถานะเปิดแชตหลังมีเส้นทางติดต่อได้
- `test/nearby_screen_test.dart`: ตั้ง database factory สำหรับทดสอบบน Windows

`dart format lib` ถูกเรียกตามคำสั่ง; `lib/screens/login_screen.dart` มีการจัดรูปแบบเท่านั้นจาก formatter นอกเหนือจากการเปลี่ยนแปลงที่มีอยู่ก่อนงานนี้ ไฟล์อื่นที่มีการเปลี่ยนแปลงเดิมใน workspace ไม่ใช่ผลงานของงานนี้

## ลำดับและแหล่งสถานะ

Hero และสถิติอยู่บนสุดทุกโหมด ตัวเลข SOS สีแดงเตือนคำขอที่ยังมีผล แม้รายละเอียดอยู่ท้ายหน้า

| โหมดของเครื่อง | ส่วนถัดจากสถิติ |
| --- | --- |
| Normal | แผนที่ → แถบที่ค้นพบ/ที่เชื่อมต่อ → อุปกรณ์ → สถานะ SOS/Rescue |
| SOS | หน่วยกู้ภัยที่มีสถานะใหม่ → แผนที่ → แถบและอุปกรณ์ |
| Rescue | คำขอ SOS ที่ยังมีผล → แผนที่ → แถบและอุปกรณ์ |

การ์ดสิทธิ์/ข้อผิดพลาดจะแสดงเพิ่มเมื่อจำเป็น โหมด SOS มาจากเหตุของเรา `mySos.isActiveAt(...)` ไม่ใช่ SOS ของอีกเครื่อง การเปิด SOS ยังใช้ขั้นตอนยืนยันข้อมูลเหตุเดิม และไม่มีการสร้างเหตุหรือรายละเอียดจำลองจากการเปลี่ยนหน้า

## การค้นหาและข้อจำกัด

- เริ่ม `startNearby()` หลังเปิดหน้า และกลับมาตรวจ/เริ่มเมื่อแอป resume หากผู้ใช้ยังต้องการค้นหา
- ตรวจสิทธิ์ตาม Android API, บริการตำแหน่ง, Bluetooth และ Wi-Fi; เมื่อไม่พร้อมมีการ์ดสิทธิ์ ปุ่มลองใหม่และเปิดการตั้งค่า
- รับอุปกรณ์ที่ค้นพบจาก Nearby callback ทันที ผู้ใช้กดเชื่อมต่อเอง ก่อนเปิดแชตต้องมีข้อมูล peer จากการเชื่อมต่อสำเร็จ
- การหยุดเองใน Hero หรือหน้าตั้งค่าการเชื่อมต่อจะปิดการเริ่มใหม่เมื่อ resume; ปุ่มเริ่ม/แก้สิทธิ์เปิดการค้นหาอีกครั้ง
- ตอนนี้ endpoint discovery ประกาศเพียงชื่ออุปกรณ์ ไม่ส่ง SOS/Rescue ก่อนเชื่อมต่อ เครื่องใหม่จึงแสดง “ยังไม่ทราบสถานะ” สถานะจริงรับผ่าน presence/relay เดิมหลังมีการเชื่อมต่อ
- ข้อมูล Rescue ต้องยังใหม่ตามอายุ presence เดิม; SOS ใช้อายุของเหตุเดิม แม้สถานะการเชื่อมต่อเก่า และไม่อ้างว่าอุปกรณ์เก่ายังติดต่อได้
- แผนที่ใช้พิกัดที่ระบบมีจริงเท่านั้น ไม่อนุมานระยะเป็นเมตรจาก Discovery
- การสลับโหมดไม่ยืนยันว่าเครื่องอื่นรับสถานะแล้ว ถ้าออฟไลน์ข้อความยกเลิกและรายละเอียดที่เลือกผู้รับยังอยู่ในคิวตามกลไกเดิม
- ไม่มีการยืนยันรับเคสหรือช่วยเหลือสำเร็จเพิ่มจากงานนี้

## การตรวจบนเครื่องพัฒนา

- `dart format lib`: เรียกสำเร็จ และจัดรูปแบบไฟล์ที่แก้ล่าสุดอีกครั้ง
- `flutter analyze`: ไม่พบปัญหา
- `flutter test`: ผ่าน 159 กรณี; 4 กรณีถูกข้าม ไม่ถือว่าผ่าน ผลบันทึกใน `output/nearby-tests.log`
- การทดสอบหน้าแรกครอบคลุมโทรศัพท์ขนาด 360×800 ทั้งธีมสว่างและมืด, ขนาด 390×844 พร้อมเลื่อนหน้า และการเริ่มค้นหาหลังกลับจากงานขอสิทธิ์
- `flutter build apk --debug --no-pub`: สร้าง APK สำเร็จ รวมโค้ด Kotlin ตรวจ Wi-Fi ไฟล์อยู่ที่ `build/app/outputs/flutter-apk/app-debug.apk`
- Build มีคำเตือนจากเครื่องมือ Java/Android SDK และ plugin `location` เรื่อง Kotlin Gradle Plugin; ไม่ทำให้ build ล้มเหลวในรอบนี้

## ต้องทดสอบบน Android จริงสองเครื่อง

ยังไม่ได้ยืนยันการทำงานกับวิทยุหรือโทรศัพท์จริงจากงานนี้

1. เปิด RescueLink สองเครื่อง เปิด Bluetooth/Wi-Fi/Location และอนุญาตสิทธิ์ที่ Android ขอ ตรวจว่าเริ่ม Advertising + Discovery และพบกันเองโดยยังไม่เชื่อมต่อ
2. ปฏิเสธสิทธิ์ ปิด Bluetooth/Wi-Fi/GPS และเปิดใหม่ผ่านการตั้งค่า ตรวจข้อความ ปุ่มแก้ไข และการเริ่มค้นหาหลังกลับเข้าแอป
3. กดเชื่อมต่ออุปกรณ์ ตรวจการตอบรับ สถานะกำลังเชื่อมต่อ/เชื่อมต่อแล้ว ส่งข้อความ แชต และเมนูตัดการเชื่อมต่อ รวมการค้นหาต่อหลังเชื่อมต่อ
4. เปิด SOS บน A และ Rescue บน B ตรวจลำดับหน้า สีและรายละเอียดบน B หลังเชื่อมต่อ เปลี่ยน/ยกเลิกเหตุ และตรวจสถานะยกเลิกบนอีกเครื่อง
5. สลับ A จาก SOS ไป Rescue และกลับไปส่ง SOS ตรวจว่าไม่เปิดพร้อมกันทั้งหน้าแรก หน้าตั้งค่า ข้อมูลที่บันทึก และสถานะที่ B ได้รับ
6. ทำ SOS ขณะไม่มีการเชื่อมต่อ จากนั้นเชื่อมต่อ B ตรวจการประกาศสถานะ คิวข้อความผู้รับ และการยกเลิกที่รอส่ง โดยไม่สูญเสียข้อมูล Local Database
7. ตรวจกรณีไม่พบอุปกรณ์/กู้ภัย/SOS, สลับแท็บ, ระยะสัญญาณหาย, เปิดแอปใหม่, เข้า background/resume และปุ่มหยุดด้วยมือ
8. ตรวจจอ Android ขนาดเล็ก ข้อความไทยยาว ขนาดตัวอักษรระบบใหญ่ และ Dark Mode จริง โดยเฉพาะ Hero รายการอุปกรณ์ แผนที่ และแถบนำทาง
