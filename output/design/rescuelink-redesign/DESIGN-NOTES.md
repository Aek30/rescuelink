# RescueLink — แบบเสนอ UX/UI

ภาพแนวทางสำหรับนำไปปรับใช้ ไม่ใช่ภาพยืนยันฟีเจอร์ที่พัฒนาเสร็จแล้ว สร้างด้วย built-in image generation; prompt ทั้งสามภาพอยู่ใน image-prompts.txt

## ปัญหาและผู้ใช้
ผู้ประสบภัยต้องขอความช่วยเหลือและสื่อสารได้เมื่ออินเทอร์เน็ตล่ม หน่วยกู้ภัยต้องเห็นคำขอและเริ่มสนทนาเร็ว ผู้ใช้ทั่วไปช่วยส่งต่อข้อมูลระหว่างอุปกรณ์ได้ โดยทุกเครื่องต้องติดตั้งแอปและเปิดความสามารถรับส่งใกล้เคียง

## โครงสร้าง 5 เมนู / 9 หน้าจอ
1. ใกล้ฉัน: สถานะอินเทอร์เน็ตแยกจากการเชื่อมต่อใกล้เคียง สวิตช์รับส่ง ค้นหาชื่อ กรองทั้งหมด/SOS/กู้ภัย รายการ SOS แดง กู้ภัยน้ำเงิน ผู้ใช้ทั่วไปและรายการพบล่าสุด
2. ข้อความ: รายการสนทนา ค้นหาประวัติในเครื่อง กรองยังไม่อ่าน / หน้าย่อยสนทนาส่งข้อความ รูป วิดีโอ พิกัด แสดงความคืบหน้าการส่ง และเส้นทางส่งต่อเมื่อมีหลักฐานจริง
3. SOS: แท็บขอความช่วยเหลือและหน่วยกู้ภัย เปลี่ยนแท็บไม่เปิดโหมดเอง / หน้าย่อย SOS กำลังประกาศ แก้ไขและปิดโหมด / หน่วยกู้ภัยเปิดปิดโหมดและแตะคำขอเพื่อแชท
4. คิวส่ง: แยกส่งให้อุปกรณ์กับซิงก์คลาวด์ ดูสถานะ สาเหตุค้าง ส่งใหม่ ความคืบหน้าสื่อ
5. ฉัน: แก้ไขชื่อและโปรไฟล์ที่เก็บในเครื่อง บัญชีและการซิงก์ สิทธิ์เชื่อมต่อ ตำแหน่ง พื้นที่เก็บข้อมูล ขนาดตัวอักษร ธีม วิธีใช้ และหน้าทดสอบ / หน้าย่อยเริ่มใช้ออฟไลน์หรือเข้าสู่ระบบ สมัครและกู้รหัสผ่านเมื่อออนไลน์

## โฟลว์หลัก
- เริ่มใช้ออฟไลน์ → ตั้งชื่อเครื่อง → อนุญาตสิทธิ์ที่จำเป็น → เปิดรับส่ง → ใกล้ฉัน → แตะคน → สนทนา
- SOS → เลือกเหตุ (มีข้อความเริ่มต้นให้) → พิกัดล่าสุดหรือไม่มีพิกัด → เปิดโหมดพร้อมยืนยันสั้น ๆ → บันทึกในเครื่องทันที → ประกาศแก่เครื่องที่ติดต่อได้ → ตรวจสถานะ/สนทนา → ปิดโหมด
- SOS → หน่วยกู้ภัย → เปิดโหมด → เครื่องอื่นเห็นน้ำเงิน → แตะคำขอแดง → สนทนา
- ส่งข้อความ/สื่อ → บันทึก local DB และไฟล์ในเครื่อง → รอ/ส่งผ่านการเชื่อมต่อใกล้เคียง → ปลายทางยืนยัน → อินเทอร์เน็ตกลับมาและมีบัญชี → ซิงก์อัตโนมัติ

## กติกาสถานะที่ต้องตรงกับระบบ
- ค้างส่ง: บันทึกในเครื่อง แต่ยังไม่ได้รับการยืนยันจากปลายทาง ระบุเหตุ เช่น ไม่พบเส้นทางหรือการเชื่อมต่อหลุด
- กำลังส่ง: สถานะระหว่างทางของสื่อ แสดงเปอร์เซ็นต์ตามข้อมูลจริง
- ส่งแล้ว: เครื่องปลายทางยืนยันรับและบันทึกสำเร็จ ไม่ใช่เพียงส่งให้เครื่องถัดไป ไม่ใช่ยืนยันว่ากู้ภัยรับงาน
- ซิงก์แล้ว: คลาวด์ยืนยันบันทึกสำเร็จ ไม่ใช้แทนสถานะส่งถึงคู่สนทนา ทั้งสองสถานะเก็บแยกกัน
- SOS/Rescue เปิดในเครื่องแล้วแต่ยังไม่มีผู้รับ: แจ้งตามจริง ไม่แสดงว่าอุปกรณ์อื่นได้รับทันทีหากยังติดต่อไม่ได้
- คนที่หลุดระยะ: เปลี่ยนเป็นพบล่าสุดพร้อมเวลา ไม่แสดงเหมือนยังเชื่อมต่อ
- ปิด SOS: ปิดสถานะในเครื่องทันทีและกระจายการยกเลิกเมื่อส่งได้ กำหนดอายุประกาศเพื่อไม่ให้สถานะเก่าค้างตลอด
- พิกัด: แสดงเวลาบันทึกและความแม่นยำ มีกรณีไม่มีตำแหน่ง และส่งข้อความ SOS ได้ต่อ ไม่สร้างระยะเมตร/แผนที่/เส้นทางสมมุติ
- การเลือกหน่วยกู้ภัยเป็นการประกาศบทบาท ไม่ใช่หลักฐานรับรองจากหน่วยงาน
- ทุกข้อมูลในภาพเป็นตัวอย่าง แต่ละหน้าจออาจแสดงคนละช่วงของโฟลว์ จำนวนคิวจึงไม่ใช่ snapshot เดียวกัน

## สิ่งที่ลด/ย้ายออก
ลด hero และคำอธิบายยาวบนหน้าฉุกเฉิน ย้าย log, รหัสเครื่องเชิงเทคนิค และเครื่องมือ demo ไปหน้าทดสอบ หลีกเลี่ยงเมนูประวัติแชทซ้ำกับข้อความ ไม่บังคับกรอกแบบฟอร์มยาวหรือล็อกอินก่อน SOS ไม่เพิ่ม social feed หรือระบบคะแนนที่ไม่อยู่ในโจทย์

## สถานะเพิ่มเติมสำหรับทำจริง
- กำลังค้นหา / ยังไม่พบเครื่อง → อธิบายให้เปิดแอปและรับส่งทั้งสองเครื่อง พร้อมลองใหม่
- Bluetooth หรือสิทธิ์ใกล้เคียงปิด → ปุ่มเปิดการตั้งค่าตรงจุด
- ไม่มีพิกัด → ข้อความไม่มีพิกัดและกรอกจุดสังเกตได้
- ไม่มีบทสนทนา → ไปใกล้ฉัน; ไม่มีคิว → ส่งครบแล้ว
- สื่อส่งล้มเหลว/พื้นที่เต็ม → คงข้อความไว้ ระบุเหตุและเสนอส่งใหม่หรือจัดการพื้นที่
- ออนไลน์แต่ session หมดอายุ → เก็บคิวไว้และให้เข้าสู่ระบบใหม่
- แก้ไขโปรไฟล์ออฟไลน์ → บันทึกในเครื่องและแสดงรอซิงก์
- ลบข้อความของฉัน → ยืนยันและระบุขอบเขตว่าลบเฉพาะในเครื่องหรือรวมสำเนาคลาวด์ ไม่อ้างว่าลบในเครื่องผู้อื่น

## ผูกกับโจทย์และหลักฐานส่งงาน
ภาพชุด 1 ครอบคลุมค้นหาอุปกรณ์ บทบาทสี แชทข้อความ/รูป/วิดีโอ และประวัติออฟไลน์ ภาพชุด 2 ครอบคลุมเปิดปิด SOS/กู้ภัย ข้อความพร้อมพิกัดและแตะสถานะเข้าแชท ภาพชุด 3 ครอบคลุมคิว ซิงก์คลาวด์ บัญชีและ local-first

การได้ครบโจทย์ต้องพิสูจน์การทำงานจริงเพิ่มเติม: D2D อย่างน้อย 2 เครื่องโดยไม่มีอินเทอร์เน็ต และ relay A → B → C อย่างน้อย 3 เครื่องโดย A ติดต่อ C ตรงไม่ได้ UI เส้นทางต้องมาจากระบบจริง รูปแบบการส่งต่อสื่อต้องกำหนดและทดสอบ ไม่ใช้ภาพต้นแบบแทนหลักฐาน ไม่รับประกันเกรดจากแบบ UX/UI เพียงอย่างเดียว

## Acceptance tests ที่เสนอ (ยังไม่ได้รัน)
1. เปิดแอปออฟไลน์และใช้ฉุกเฉินโดยไม่สมัคร
2. ค้นพบและเชื่อมต่อมือถือจริง 2 เครื่องโดยไม่มี infrastructure
3. A เปิด SOS แล้ว B เห็นแดงและข้อความ/พิกัด
4. B แตะ SOS เปิดแชทถูกคน
5. B เปิดกู้ภัยแล้ว A เห็นน้ำเงิน; ปิดแล้วสถานะหาย/เปลี่ยนตามข้อมูลจริง
6. ส่งข้อความออฟไลน์ รับ ACK แล้วแสดงส่งแล้ว
7. ส่งรูปและวิดีโอออฟไลน์ เปิดไฟล์ปลายทางได้
8. หลุดการเชื่อมต่อระหว่างส่งแล้วกลับมาต่อ ไม่สร้างข้อมูลซ้ำ
9. ปิดเปิดแอปแล้วยังอ่านประวัติและสื่อ local ได้
10. อินเทอร์เน็ตกลับมาแล้วคิวซิงก์และสถานะตรงกับคลาวด์
11. ไม่มี GPS/ปฏิเสธสิทธิ์แล้วส่ง SOS พร้อมจุดสังเกตได้
12. A → B → C รับส่งได้เมื่อ A ติดต่อ C ตรงไม่ได้ ตรวจป้องกันวนซ้ำและ ACK
13. ขยายตัวอักษร/ใช้ screen reader แล้วเมนูและสถานะยังเข้าใจได้
14. ปิด SOS ขณะหลุดการเชื่อมต่อ แล้วเมื่อกลับมาเชื่อมต่อเครื่องอื่นได้รับการยกเลิก
